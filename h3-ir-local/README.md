# H3-IR Local · 本地创作工作台

本地 REST 服务 + 单 HTML 中文界面。界面使用固定版本 Vue 3 CDN，不需要 Node、npm 或前端构建。
编译能力来自 **`open-h3-ir==0.4.1`**，不复制、不重写编译规则。

**Local 指服务、界面、请求和结果在本机运行、保存，不表示模型必须在本机。**
语言／视觉模型通过 HTTP 连接，可以是另一台机器上的 Ollama、LM Studio、llama.cpp、vLLM 或兼容 API。
素材会发送给你配置的模型端点；使用远程端点前请确认其隐私与数据处理政策。
本应用只编译 H3 Context-IR，不运行 H3 视频模型，也不渲染成片。本机不需要 CUDA。

## 启动

需要 Python 3.10+，推荐 3.12。以下为 PowerShell 命令：

```powershell
Set-Location C:\dev\open-h3-ir\h3-ir-local
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\h3-ir-local.exe
```

使用 uv：

```powershell
uv venv --python 3.12
uv pip install -e .
.\.venv\Scripts\h3-ir-local.exe
```

打开 <http://127.0.0.1:8421>。API 文档：<http://127.0.0.1:8421/docs>。
端口可通过 `h3-ir-local --port 8422` 修改。仅监听 `127.0.0.1`，默认不向局域网开放。
请通过服务打开页面，不要直接双击 HTML。

### 与当前源码一起开发

此目录是独立的 Python 项目；不依赖父目录布局。当前仓库位于 `0.4.1`，
开发验证基于父仓库提交 `fd031e136ae3d89147324c0d1b2aa65e838c21f5`。
如果要测试当前 checkout，而不是从包索引安装固定版本：

```powershell
# 在 h3-ir-local 目录，且已经创建虚拟环境
uv pip install -e .. -e ".[dev]"
```

父项目不能改成其他版本而仍假定适配器兼容。启动时会检查安装版本。
发布或独立部署时应安装固定版本的正式包；editable 安装只用于开发，不会冻结源码内容。

当前 checkout 额外修复了 Windows 素材分析缓存的 UTF-8 读写问题：
图片中的中文、日文等原文不再因系统默认 `cp1252` 编码导致缓存写入失败。
这个修复位于父目录的编译核心；仅安装未经修复的正式 `0.4.1` 包不会获得该修改。
遇到 `UnicodeEncodeError` 时，请使用上面的源码开发安装方式，重启服务后重新提交任务；
失败的任务不会自动重跑，损坏的缓存会按原核心策略作为未命中重新分析，无需删除整个缓存目录。

当前 checkout 也为视觉分析添加了图片预处理，避免高分辨率原图直接 Base64 编码后，
因模型端点或代理的请求体限制而收到 HTTP 413：

- 归档、下载和 H3 首帧／参考使用的原文件不变。
- 仅发给视觉模型的分析副本，默认最长边不超过 2048 像素；
  一次图片消息中的全部图片共用 512 KiB 的编码前字节预算，视频采样帧也共用该预算。
- 小图片保持原始字节；超限图片等比缩小并转为 JPEG，应用 EXIF 方向，透明部分合成白底。
  JPEG 质量依次尝试 90、80、70，仍超限则继续缩小；不放大小图。
  细小文字等细节可能损失，控制台会记录实际分析尺寸与字节数。
- 服务启动前可设置 `H3IR_VISION_MAX_EDGE` 和 `H3IR_VISION_IMAGE_BUDGET_BYTES`。
  调大可保留更多细节；端点仍返回 413 时可调低字节预算。某项设为 `0` 关闭该限制，
  两项均为 `0` 恢复发送无界原图。预算不包括 Base64 增量、提示词和 JSON，
  不能保证适合所有端点的请求体限制。
- 缓存版本与预处理参数一起参与缓存键，修改参数不会误用旧分析结果。

此修改同样需要上述源码开发安装方式（新增 Pillow 依赖），安装后重启本地服务。
已有记录与附件无需删除或重新上传；载入后重新编译即可，旧失败记录不会被覆盖。

## 使用流程

### 多附件编号与正式 slot

上传卡片显示“附件 1、附件 2……”、原文件名、预览及独立的角色／参考说明。
每张卡片的说明只绑定该附件，不靠说明里的文件名寻找图片。此编号只是当前列表顺序，
移除附件后会重新编号，不能当作总需求中的引用标签。

编译前不预测 `<Picture N>` 或 slot：核心会根据首／尾帧角色和运行时接线顺序分配，
不保证等于上传顺序。完成后，“素材接线”逐项显示结果 manifest 的正式标签、从 0 开始的
slot、角色、接线名和对应原文件；历史附件卡片也显示本文件在结果中的标签。
匹配使用 SHA-256 与素材类型，不靠文件名或列表位置；同一文件的重复用途全部列出。
没有匹配记录时明确提示，并保留原始接线 JSON 供核对。

### 提交编译

1. 在页面中填写模型 API 基地址、模型名和可选密钥，保存连接。
   多模型端点请明确指定视觉模型。测试连接只验证端点可达与模型解析，不验证视觉能力。
2. 输入需求、时长、画幅、创意许可；可设置导演、固定镜头数、台词、画面文字和约束。
3. 选择图片／视频／音频。素材角色来自已安装核心的契约，不另造一套枚举。
   默认可让核心推断；替换主体时填写“替换谁”，视频音轨应选择它所属的视频。
4. 点击编译。浏览器按 SHA-256 上传素材，通过 HTTP 提交任务，服务后台执行编译。
   页面使用 SSE 接收实际阶段、耗时和最终结果，不再定时查询任务或历史。
5. 查看提示词、创作说明、素材接线、校验信息及完整 JSON。支持复制与下载。
6. 用自然语言继续修改，产生新任务和新版本，旧结果保持不变。

每次只执行一个编译任务；运行时拒绝额外提交及连接配置变更，避免核心的进程级配置相互污染。
模型请求可能耗时数分钟。关闭浏览器不会取消任务；重新打开页面可从历史中查看。
服务重启会将未完成任务标记为“已中断”，不会伪装成成功，也不会自动重复消耗模型调用。

### 实时阶段（HTTP + SSE）

`POST /api/jobs` 返回 `202` 和任务 ID 后，订阅 `GET /api/jobs/{id}/events`。
自然语言修改也使用同样的方式回传。事件示例：

```text
retry: 2000

id: 5
event: job
data: {"id":"…","status":"running","revision":5,"progress":[…],"result":null,…}

```

- `event: job` 的 `data` 是任务的公开完整快照，包括累计 `progress` 阶段记录；
  不包含内部修改上下文或模型密钥。`id` 为单调递增的快照版本号。
- 阶段在核心实际进入对应操作前报告，不按定时器伪造阶段或百分比。
  默认 write-first 路径包含需求检查、模型连接、素材分析、模式判断、确定性草稿、
  完整 IR 撰写、校验；按需出现修正轮次和草稿回退。
  分阶段生成路径另有镜头规划、节拍和逐镜头撰写。
- 页面显示累计耗时，阶段历史中的秒数为进入该阶段时的累计耗时，不是预计剩余时间。
  长时间停留在同一阶段意味着正在等待该操作，例如模型调用。
- 每 15 秒发送 `: heartbeat` 注释保持连接，不代表编译进度。
- 断线由浏览器 EventSource 自动重连，页面明确提示重连状态。
  无论是否带 `Last-Event-ID`，重新订阅都先返回最新持久化快照及全部阶段历史，
  不逐条补发旧快照；因此不会漏掉当前状态，也不会重新执行编译。
- 完成、失败或中断时发送最终快照并关闭流，浏览器主动关闭 EventSource，避免终态重连。
  页面刷新后可从历史恢复正在运行任务的订阅。关闭浏览器只断开订阅，不取消任务。
- 服务禁止响应缓冲（`X-Accel-Buffering: no`）。若自己增加代理，也需要允许 SSE 流式传输。

详细阶段依赖当前 checkout 在核心中新增的可选 `progress(stage, message)` 回调。
它不改变提示词、校验规则或生成策略；原调用者省略该参数时保持原行为。
**使用上述源码开发安装方式才能获得这些细分阶段。**
未经此扩展的正式 `0.4.1` 仍可运行，但只能报告“编译中（此核心版本不提供详细阶段）”等外层状态，
不会凭空猜测核心内部进度。

每条历史记录只保存一套可继续编辑的参数；自然语言修改成功后，以实际生效的参数更新，
不再额外保存修改前的原始参数快照或当时的模型／编译配置。
点击左侧“最近创作”会同时选中结果并自动填充上方唯一的编辑表单，包括归档附件；
页面首次打开时也会恢复最新记录。使用本版本实际生效的需求、时长、镜头数及约束，
而不是退回最初的需求。切换历史、新建或重置输入前，如果存在尚未提交的参数、
附件编辑或自然语言修改指令，会先请求确认；取消不改变当前表单和结果。
载入期间暂时锁定编辑和其他历史选择，读取失败时保留当前输入。
实时阶段更新不会重新填充、覆盖正在编辑的表单。
最终交付仍以提示词为准；自然语言修改是模型解释后的结构化结果，不保证另一轮调用会生成逐字相同的输出。

### 创作记录与附件归档

上方表单集中展示和编辑附件，保留预览、缺失提示及原文件下载，不在结果区重复展示附件卡片。
不再提供“查看原始创作记录与配置”、完整记录导出或历史模型设置恢复。
保留继续创作所需的数据：

- `request`：本版本的全部核心参数，包含展开后的默认值、精确台词、画面文字、
  约束、导演、创意许可、种子、分辨率、工作量、转录、素材角色、配对和来源信息。
- `change`：本次修改指令；成功修改后实际生效的结构化需求直接写入 `request`。
  修改失败时保留输入基线，不伪造成功修改后的参数。
- `attachments`：按输入顺序保存文件名、类型、字节数、SHA-256，以及原文件是否可用。
  原文件独立保存于 `creations/<记录ID>/attachments/<SHA-256>`，不受核心上传缓存的过期或 LRU 清理影响。
  每次编译和继续修改都复制自己的附件，不跨记录共享文件或使用硬链接；
  同一记录中重复使用同一个文件时只保存一份。
  图片可预览，视频／音频可播放，原文件可分别下载。
- 输出、诊断、执行阶段和状态，以及继续修改所需的内部上下文。
  **API Key 不进入历史。**

历史按创建时间保留最近 **100 条**，写入时会实际删除超出范围的旧记录，而不是只隐藏列表。
排队或运行中的任务不清理，因此保护期间可能暂时超过 100 条；任务结束后再次执行保留策略。
服务重启时先将遗留未完成任务标为中断，再清理旧记录。连接设置不受记录清理影响。
旧父记录被清理后，保留的子版本仍可独立继续修改。
手动删除或自动淘汰记录时，一并删除该记录的整个附件目录，不扫描其他记录的文件引用。
排队或运行中的记录及目录不删除；文件删除失败会明确报错，不返回删除成功。

记录创建前先复制并校验附件；磁盘写入失败、附件缺失或哈希不匹配会明确拒绝，
清理未接受任务的目录，不会创建一个缺少附件的新任务。
编译直接读取归档文件。重新编辑后提交时，适配器会在必要时通过核心有大小／容量限制、
且验证哈希的上传接收器恢复临时副本，以复用原有请求转换和拒绝规则；
因此新的编译仍受当前上传限制约束，但临时缓存清理不会抹掉历史原文件。
重新编译历史输入时，页面发送 `source_job_id`，服务直接从来源记录复制原文件；
成功接受后不再依赖来源记录。继续修改也先复制附件，再使用新版本自己的文件编译。

载入输入会恢复原文件名、预览、素材角色、说明、替换对象、音视频配对及转录，
无需在浏览器重新选择已经归档的文件。未单独显示控件的 API 参数也会随输入保留。
模型连接不会被历史选择切换，重新编译统一使用当前连接设置。
编辑区的“还原参数”可放弃当前编辑，再恢复所选版本；有未提交修改时会请求确认。

结果区仍可下载提示词 TXT 和编译结果 JSON；附件原文件分别下载。
若要迁移整套工作区，请在服务停止后备份整个数据目录，记录 JSON 与附件需要一起保留。

仅使用上述独立目录结构，不提供旧版共享归档或原始快照的数据兼容、启动迁移逻辑。
从旧版部署切换时，应先清空旧创作及其共享归档；当前模型连接设置可以保留。

## 数据与配置

- 默认数据目录：用户主目录下的 `.h3-ir-local`。
- 可在启动前设置 `H3LOCAL_DATA_DIR`，例如：

  ```powershell
  $env:H3LOCAL_DATA_DIR = "D:\h3-local-data"
  .\.venv\Scripts\h3-ir-local.exe
  ```

- `creations/<记录ID>/record.json` 是该创作唯一的持久化记录，保存参数、文件清单、结果、
  状态、阶段和内部修改上下文；不使用数据库，也不另外维护历史索引。
- `creations/<记录ID>/attachments/` 是该记录自己的附件副本；
  删除记录会清理整个 `creations/<记录ID>/`。
- `settings.json` 单独保存当前非敏感模型连接设置，不随创作删除。
- JSON 使用 UTF-8 和缩进，阶段更新会替换同一份记录，不累积快照文件。
  写入先完成同目录临时文件并同步磁盘，再原子替换；失败会报错并清理临时文件，
  原有 JSON 不会被截断。损坏的记录或配置会明确报错，不被当作“没有历史”忽略。
- `core` 保存原编译器的分析缓存与上传素材。
- 页面 API Key **只存服务进程内存**，不写 JSON、不返回浏览器、不存 localStorage；
  留空保留当前会话密钥，使用“清除密钥”删除。重启后重新填写，或使用原核心支持的 `H3IR_LLM_KEY` 环境变量。
- 模型端点和模型名默认继承原核心的 `H3IR_LLM_URL` / `H3IR_LLM_MODEL`；
  页面保存的非敏感配置在后续启动时优先。
- 上传数量、大小、临时缓存容量和过期策略沿用核心，页面从能力接口读取。
  被创作记录引用的文件复制到独立目录，不随缓存清理，而是随记录一起删除。
  100 条限制的是记录数量，不是总附件字节数；大视频的多版本副本会增加磁盘占用。
- 浏览器计算 SHA-256 时会读取整个文件，较大视频会占用对应内存；服务端仍为流式接收。
- Vue 固定为 `3.5.13`，CDN 地址统一放在 [config.py](h3_ir_local/config.py)。
  首次加载需要联网，加载失败会明确提示。不宣称完全离线运行。

## REST 接口

修改类请求必须带 `X-H3-Local: 1` 请求头。浏览器页面已自动添加；
服务不开放 CORS，带 `Origin` 的写请求必须同源，并限制合法 Host，降低恶意网页调用本机服务的风险。
这是单用户本地应用，没有多用户认证，不要通过反向代理公开到公网。
Swagger 的“Try it out”默认不附带该头；写请求可使用下面的 PowerShell 示例或其他 REST 客户端。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 单 HTML 页面 |
| GET | `/api/health` | 本地服务状态及 FFmpeg/ffprobe 可用性 |
| GET | `/api/bootstrap` | 核心契约、能力、非敏感配置 |
| GET / PUT | `/api/settings` | 读取／保存连接设置 |
| POST | `/api/probe` | 测试已保存的模型连接 |
| PUT | `/api/assets/{sha256}` | 原始字节上传，复用核心的哈希校验、上限和去重 |
| GET | `/api/jobs` | 最近 100 条任务摘要 |
| POST | `/api/jobs` | 提交编译，返回 `202` 和任务 ID |
| GET | `/api/jobs/{id}` | 请求、状态、结果、错误 |
| GET | `/api/jobs/{id}/assets/{index}` | 读取记录中指定序号的归档附件；`?download=true` 下载原文件 |
| DELETE | `/api/jobs/{id}` | 永久删除单条非运行中的创作及其独立附件目录，返回 `{"id":"…","deleted":true}` |
| GET | `/api/jobs/{id}/events` | SSE 任务快照、实际阶段历史和最终结果 |
| POST | `/api/jobs/{id}/refinements` | `{"change":"…"}`，从已完成任务生成新版本 |

```powershell
$headers = @{ "X-H3-Local" = "1" }
$body = @{ intent = "A lighthouse keeper lights the lamp in a storm."; seconds = 10 } | ConvertTo-Json
$job = Invoke-RestMethod "http://127.0.0.1:8421/api/jobs" -Method Post `
  -Headers $headers -ContentType "application/json" -Body $body
Invoke-RestMethod "http://127.0.0.1:8421/api/jobs/$($job.id)"
```

编译请求直接使用原核心的 `BriefIn` schema，并禁止未知字段。
本地接口额外接受 `asset_names`：与 `assets` 同序的原文件名数组；
不传表示原文件名未知，数组项 `null` 也表示未知，不将哈希冒充为原文件名。
可选 `source_job_id` 指定重新编译时从哪条现有创作复制附件；它不进入核心参数，
也不会形成新记录对来源文件的持续依赖。来源已删除时明确返回 `404 unknown-source-job`。
为限制本机文件访问，素材只接受已上传的 `sha256`，不接受 `path`、URL 或 `paired_video_path`。
API 可发送 UI 未专门展示的核心字段，例如 LoRA 配置和来源记录，但原核心的缺陷也会继承。
任务 `status` 为 `completed` 只表示编译成功；是否交付确定性草稿，请同时查看
`result.source` 和 `result.fallback_reason`。所有失败都有明确错误，异常也记录在终端日志中。

“最近创作”每条记录右侧提供删除按钮，确认后永久删除该版本的请求、结果、错误和内部修改上下文。
等待中或编译中的任务禁止删除（`409 job-active`）；已完成、失败或中断的记录均可删除。
删除不存在的任务返回 `404 unknown-job`，重启服务后不会恢复已删除记录。
只删除选中的版本及其独立附件，不级联删除其他版本；核心临时上传和分析缓存仍独立管理。
已有后续版本保留自己的完整修改上下文，仍可继续修改；其 `parent_id` 作为历史来源 ID 保留，不保证该记录仍存在。
删除当前查看的记录会清空结果区，但保留正在编辑的创作表单；
仍指向被删除记录的已归档附件会标为缺失，需要重新选择文件，不假装还能提交。
如果 SSE 订阅与删除恰好并发，订阅会收到 `event: job`、`{"id":"…","status":"deleted"}` 后结束；
已经删除的 ID 新建订阅仍返回 `404`。

## 边界与已知限制

- 图片分析需要视觉模型；没有 CUDA 不影响本应用开发与结构校验，但不代表不需要模型服务。
- 视频分析依赖 PATH 中的 `ffmpeg` 和 `ffprobe`，只抽取 10% / 50% / 90% 三帧。
- 音频不自动转录、也不会被模型听懂。填写真实转录，以及音色、节奏等已知事实。
- LoRA 的已知问题沿用 `0.4.1` 核心，首版没有把它包装成成熟的 UI 功能。
- 自然语言修改沿用核心，会重新执行编译，不宣称是局部增量更新。
- 本地服务的连通性测试不代替核心 `h3ir doctor` 的视觉探测。
- 创作计划属于核心返回的辅助信息；write-first 路径的计划可能来自确定性草稿，
  最终交付以 `result.ir.prompt` 为准，不用计划中的镜头数冒充实际提示词中的镜头数。
- 不保证人物一致性、精确视频编辑或最终成片质量；这些需要在 H3 渲染环境中验证。
